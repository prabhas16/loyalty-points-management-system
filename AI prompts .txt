# PROJECT: ENTERPRISE LOYALTY POINTS MANAGEMENT & AUDITABLE LEDGER PLATFORM

## 1. YOUR ROLE

Act as a Senior Full-Stack Software Architect, UI/UX Designer, Backend Engineer, Database Architect, Data Engineer, QA Engineer, and Business Analyst.

Build a complete, functional, end-to-end Loyalty Points Management Platform with a modern frontend, scalable backend, relational database, synthetic data generator, auditable transaction ledger, business rule engine, validation framework, and analytics dashboard.

This must be a working application, not a static UI prototype.

All frontend screens must connect to real backend APIs, and all business operations must persist to the database.

Do not use mock responses for core business functionality. Implement actual business logic, database transactions, validations, and error handling.

## 2. BUSINESS OBJECTIVE

Build a loyalty management system that supports the complete lifecycle of loyalty points:

1. Customer registration and loyalty account creation.
2. Loyalty tier configuration.
3. Earning rate and rule configuration.
4. Points accrual from eligible purchases.
5. Points redemption against available balances.
6. Full and partial order returns.
7. Reversal of previously earned points.
8. Points expiration based on expiry dates and earning lots.
9. Tier progression based on qualifying spend.
10. Concurrent redemption handling.
11. Auditable transaction history.
12. Anomaly detection and exception management.
13. Synthetic data generation at configurable scale.
14. Data validation and reconciliation.
15. Ground-truth anomaly classification.
16. Reproducibility verification.

The application must provide complete traceability from customer and order records to every points transaction.

### Module 7: Points Accrual Engine

Implement the actual points earning logic.

Formula:

Eligible Net Spend = Gross Spend - Discounts - Refunds - Non-Eligible Amount

Points Earned = FLOOR(Eligible Net Spend / Earning Threshold) × Applicable Earning Rate

Apply tier and rule configurations.

Workflow:
1. Receive completed order.
2. Validate customer and loyalty account.
3. Validate order eligibility.
4. Calculate eligible net spend.
5. Identify applicable tier.
6. Identify applicable earning rule.
7. Calculate points.
8. Create points accrual ledger transaction.
9. Create an earning lot with its expiry date.
10. Update account balance within a database transaction.
11. Record an audit event.

Prevent duplicate accrual using an idempotency key.

### Module 10: Returns and Points Reversal

Support full and partial returns.

When an order is returned:
1. Retrieve the original order.
2. Retrieve the original accrual transactions.
3. Determine the returned eligible amount.
4. Calculate proportional points to reverse.
5. Verify previously earned points.
6. Create a reversal transaction.
7. Link reversal to the original accrual.
8. Reconcile the remaining points.
9. Update qualifying spend.
10. Recalculate tier eligibility.
11. Record the return event and audit history.

Do not silently overwrite the original accrual.

If the customer has already redeemed the points, handle the resulting negative-balance or recovery policy according to a configurable business rule.

Support partial and full returns separately.

### Module 11: Points Expiration Engine

Implement lot-based expiration.

Every accrual creates a points lot with:
- earning_lot_id.
- original_transaction_id.
- loyalty_account_id.
- original_points.
- remaining_points.
- earned_date.
- expiry_date.
- lot_status.

Use configurable expiration policies.

Default policy: points expire 365 days after earning.

Expiration workflow:
1. Identify lots reaching expiry.
2. Verify remaining points.
3. Verify the lot has not already expired.
4. Calculate remaining eligible points.
5. Create an EXPIRATION ledger debit.
6. Link the expiration to the original earning lot.
7. Update lot remaining points.
8. Mark the lot expired.
9. Record the expiry batch.

ExpiryBatch fields:
- expiry_batch_id.
- execution_date.
- processed_lot_count.
- expired_points.
- batch_status.
- error_count.
- created_at.

Expiration ID convention:

EXP-2026-000001

Expiration must be idempotent. Running the same expiration job twice must not expire the same points twice.

### Module 13: Exception and Anomaly Management

Create a dedicated exception management center.

Detect and classify the following five mandatory anomalies:

1. BALANCE_MISMATCH:
   Account balance differs from the net sum of posted ledger entries.

2. REDEMPTION_EXCEEDS_BALANCE:
   Redemption request exceeds available points.

3. RETURN_WITHOUT_REVERSAL:
   Returned order retains all or part of the points that should have been reversed.

4. DUPLICATE_EXPIRATION:
   The same earning lot is expired more than once.

5. INCORRECT_TIER_CALCULATION:
   Tier progression uses gross spend instead of qualifying net spend.

Additional exception categories:
- Duplicate accrual.
- Missing reversal reference.
- Invalid customer reference.
- Expired reward.
- Invalid account status.
- Concurrent redemption conflict.
- Missing earning lot.
- Negative balance.
- Invalid rule effective date.
